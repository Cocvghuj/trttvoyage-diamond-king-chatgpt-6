# Next Project Preparation — SaaS Universe MVP Discovery 001

**Project code:** DR-TRTT-OPS-001  
**Prepared:** 2026-11-28  
**Status:** READY FOR OWNER TRIGGER — discovery only; no implementation authorization implied.

## Why this is the next project

The Command Center and Learning Journey now provide a visual direction, browser-local learning plans, browser-local idea capture, and a public learning path. The next unresolved product question is how to turn those separate prototypes into a genuinely useful, secure, multi-user workspace without pretending the existing static pages are already SaaS.

## Proposed project outcome

Produce an evidence-backed MVP definition for the proposed **SaaS Universe**. The deliverable should let the Owner decide whether to build, revise, or stop before any paid service, production deployment, or sensitive data is introduced.

## Discovery scope

1. **Problem and users:** identify the first user group and one painful workflow worth solving; do not assume market demand.
2. **Core workflow:** map one end-to-end path for creating a project, recording a decision, attaching evidence, tracking a milestone, and exporting the user's records.
3. **MVP boundary:** distinguish must-have, later, and explicitly excluded features. Start with one workspace and one owner; defer franchise tenant management until isolation requirements are proven.
4. **Data ownership:** define record ownership, export format, deletion/retention expectations, and what is private by default.
5. **Security and privacy:** threat model, least-privilege access, authentication options, session handling, audit events, backup/restore, and safe handling of user-provided files.
6. **Architecture options:** compare free-tier-capable approaches for frontend, database, authentication, storage and hosting. Verify current limits and terms before selecting anything.
7. **Acceptance and test plan:** define observable acceptance criteria, abuse cases, accessibility checks, backup/restore tests, and operational monitoring before implementation.
8. **Decision pack:** recommend Build / Revise / Stop with evidence, costs (including zero-cost constraints), risks and unresolved questions.

## Proposed first vertical slice

- Create one project workspace.
- Add one decision record with owner, date, context and status.
- Attach one HTTPS source/evidence reference.
- Add one milestone and next action.
- Export the workspace records in a documented portable format.

This is a candidate for validation, not an approved final feature list.

## Non-goals for the first discovery cycle

- No automatic ingestion of private ChatGPT conversations.
- No claim of live ChatGPT Memory ↔ GitHub synchronization.
- No billing, subscription, franchise licensing, public user directory, or revenue claims.
- No production deployment, DNS change, live publication, or paid API/service.
- No collection of sensitive personal or health data.
- No migration or deletion of existing local browser records.

## Required deliverables before implementation

- Problem statement and target-user hypothesis.
- One user journey and low-fidelity screen map.
- MVP requirements and non-goals.
- Data model and ownership/retention rules.
- Threat model and privacy review checklist.
- Free-tier architecture comparison with current source links.
- Test/acceptance matrix and rollback/backup plan.
- Owner decision record approving, revising or rejecting the MVP scope.
