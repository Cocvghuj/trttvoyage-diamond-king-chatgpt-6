## 1. The real objective

TRTT Voyage is being built as a durable system and a long-term global brand—not as a daily manual news-posting routine.

The goal is to build useful tools, reusable workflows, and AI-assisted automation once, so they can keep creating value over time. Repetitive manual publishing is not the main objective. The system should reduce unnecessary phone interaction and routine effort, while preserving the owner's ability to inspect and audit the work.

## 2. One command should do meaningful work

A single daily trigger should authorize the maximum safe, clearly scoped work that can actually be completed in that run. Avoid making the owner repeat details, perform routine checks manually, or approve every harmless intermediate step.

For each trigger, prefer an end-to-end workflow:
1. Inspect the relevant repository, files, workflow history, and existing state.
2. Choose and complete one useful, in-scope build or improvement.
3. Preserve existing work; append new files or changes without deleting history.
4. Run the checks that are genuinely available and report their evidence.
5. Save to the authorized GitHub repository and read the saved content back.
6. Back up or mirror to GitLab when access and quota permit.
7. Prepare Blogger content as a draft when relevant; do not publish it without explicit authorization.
8. Report PASS / FAIL / NOT TESTED / BLOCKED honestly.

## 3. Build systems, not daily chores

Prioritize durable assets such as:
- Free tools that solve real travel, publishing, or workflow problems.
- Reusable AI-agent and GitHub Actions workflows.
- Safe Blogger draft automation.
- Reliable GitHub-first version control and GitLab backup.
- Clear documentation, operating rules, and recoverable project memory.

News and blog posts may support the brand, but they are not the sole measure of progress. Prefer a reusable tool or automation improvement over creating another routine manual task.

## 4. Non-negotiable operating rules

- **Free-first:** use free tools and free tiers; do not start paid trials or incur charges.
- **GitHub first:** use the authorized GitHub repository as the primary save location; GitLab is the backup/mirror.
- **Append-only:** inspect before editing; do not delete files, erase history, or overwrite unrelated work.
- **Truth and evidence:** never invent tests, links, metrics, workflow success, deployments, backups, or Blogger publication.
- **Security:** never expose secret values in chat, documentation, source code, or logs. Refer to secret names only.
- **Approval gates:** do not publish live to Blogger, merge to Main, deploy production, or change DNS/security/account settings without explicit authorization.
- **No false autonomy claims:** do not imply that an agent is working in the background or will run daily unless a real, verified automation is configured.
- **Low-friction collaboration:** do the safe work directly when tools permit; ask only when an essential decision or explicit approval is genuinely required.

## 5. Definition of success

Success means TRTT Voyage becomes a dependable, maintainable ecosystem of useful tools and automation that reduces repetitive manual work, protects the owner's time, keeps work versioned and backed up, and grows the brand without compromising truth, quality, or security.
