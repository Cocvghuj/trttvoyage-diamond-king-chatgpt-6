# Contributing

Contributions must be focused, traceable, secure, and supported by evidence.

## Before contributing
1. Read the README and relevant documentation.
2. Search existing issues and pull requests to avoid duplicates.
3. Discuss substantial changes before implementation.
4. Never include secrets, personal data, private records, or unlicensed assets.

## Delivery workflow
1. Create a focused feature or fix branch from the default branch.
2. Keep each change limited to one purpose.
3. Update documentation when behaviour, interfaces, security, or operating steps change.
4. Run relevant checks and state exactly what was and was not tested.
5. Open a pull request using the repository template.
6. Address review feedback and verify the resulting base branch after merge.

Do not push directly to the default branch. Production, account, DNS, billing, privacy-sensitive, and security-control changes require the appropriate Owner approval.

## Quality checklist
- [ ] Scope and acceptance criteria are clear.
- [ ] No secrets, tokens, private data, or generated credentials are included.
- [ ] Links and claims are accurate.
- [ ] Accessibility and mobile impact are considered where relevant.
- [ ] Tests and limitations are reported honestly.
- [ ] Risks and recovery notes are documented.

Use dependencies only when justified. Review maintenance, permissions, licenses, and known vulnerabilities. Do not copy code or assets without permission and required attribution.
